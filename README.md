# 見積・スケジュールメーカー

GitHub Pagesでの公開手順は [DEPLOY.md](DEPLOY.md) を参照してください。自動テスト・ビルド・公開用のGitHub Actions設定を同梱しています。

Excelの見積から、予定完了日・月間カレンダー・ガントチャートを生成するローカルアプリです。Vite + Reactで構成し、バックエンドやDB、Dockerは使いません。ファイルを外部へ送信する処理や外部フォント・CDNはありません。

## 使い方（サーバー不要）

`dist/index.html` をブラウザーで開いてください。JavaScriptとスタイルはHTMLに同梱しています。インターネット接続は不要です。

1. 「見積を取り込む」からExcelを選択。
2. 内容を確認して「この計画に切り替える」。現在の計画は先にJSONでバックアップできます。
3. 着手日、日当、毎週の休業日、追加の休業日を設定。
4. 「納品単位を追加」で工程のグループを作り、グループ内の「工程を追加」で登録します。納品単位ごとに制作日・予備日・計画日数・制作費・開始日・完了日の小計を表示します。納品単位番号は表示順で1から自動採番し、単位が削除された場合も欠番を詰めます。既存・取り込みデータも、工程の所属を保って連番へ変換します。項目名は表の先頭1行にまとめ、表内のスクロール中も固定表示します。
5. No.の左側のハンドルをドラッグして工程の順番を変えると、自動で予定を再計算。別の納品単位の工程へドロップすると、その納品単位へ移動します。キーボードではハンドルにフォーカスして上下キーでも移動できます。
5. カレンダーとガントチャートで予定を確認。
6. 「書き出す」から予定一覧CSV、カレンダーICS、バックアップJSON、印刷/PDFを出力。

保存先はブラウザーのlocalStorageです。保持する計画は1つです。別ブラウザー・端末・ファイルの移動では保存領域が共有されない場合があるため、計画の切替やファイル移動の前にJSONを保存してください。JSONは同じ取り込みボタンから復元できます。ブラウザーがローカルファイルの保存を制限している場合は画面で通知します。

## PWAとしてインストール

HTTPSで公開したサイト（GitHub Pagesなど）を開き、Chrome / Edgeのインストールメニュー、またはiPhone / iPadのSafariの共有メニューから「ホーム画面に追加」を選択してください。独立したウィンドウで利用できます。

本番ビルドはアプリ本体とアイコンをService Workerに保存します。初回のオンライン読み込みとキャッシュ保存が完了すると、再アクセス時にオフラインでも利用できます。更新は開いているアプリのウィンドウ・タブをすべて閉じてから開き直すと反映されます。計画の保存先は引き続き同じ公開URLのlocalStorageです。ローカルHTML版・別URLのデータとは共有されないため、移行時はJSONを書き出して取り込んでください。

`file://`で開く単一HTML版と開発サーバーではService Workerを登録しません。PWAで公開するときは`dist`フォルダ全体を配信してください。アイコンの元データは`public/icon.svg`、PNG再生成はWindows PowerShellで`./scripts/generate-icons.ps1`を実行します。

## 対応Excel

- `.xlsx`, `.xls`, `.csv`、最大20MB。複数シートのうち、対応ヘッダーが最初に見つかった表を読み込みます。
- 必須：`工程・納品物` と `制作日`。別名 `工程` / `作業名` / `タスク名`、`制作日数` / `基本日数` / `工数` も対応。**工数は日単位**です。
- 任意：`予備日`（または`予備日数`）、`納品単位`、`キャラクター／対象`、`分類`、`つなぐ仕事依頼`。元のExcelの「キャラクター／対象」は画面の「分類」へ読み込みます。その列がない場合は「分類」列を使います。案件名と元の分類は内部に保持しますが、表に2行目としては表示しません。
- 納品単位は0以上の整数。未指定・旧保存データの初期値は1です。工程の管理用の番号で、制作費・工数への乗算は行いません。CSVとJSONにも保存します。
- `単価・設定`シートのA列に`日当`で始まるラベルがある行のB列から日当を、`着手日`で始まる行のB列から着手日を読み込みます。未指定時は日当10,000円・取り込み日を初期値にします。
- 休業日は初期値で金曜・日曜です。元ファイルのカレンダーからの休業日抽出はしません。取り込み後に確認・変更してください。
- 元の予定完了日・制作費・カレンダー・注記・マクロは実行も取り込みもしません。元のExcelファイルは変更しません。
- 計画は最大500工程、制作日＋予備日は合計5000日、各日数は0〜1000日。空の工程名の行は取り込み対象外です。

## 計算ルール

納品単位番号の横に、任意のタイトル（200文字以内）を入力できます。タイトルは端末保存・JSONバックアップ・CSVで保存でき、PDFと印刷の納品単位見出しにも表示します。工程の追加・削除や納品単位の再採番後もタイトルを保持します。工程を別の納品単位へ移動した場合は移動先のタイトルに従います。

- 工程は納品単位ごとにまとめ、最初に登場した納品単位の順・グループ内の工程順で、制作日→予備日の順に連続配置します。既存の工程も納品単位ごとにまとめます。納品単位未指定の旧データは1として扱います。並行作業や依存関係の個別設定はありません。最後の工程を削除した納品単位は表示から消えます。
- 納品単位ごとの小計は画面・PDF・印刷・CSVに表示します。CSVの小計行は再取り込み時に工程として読み込まず、二重計上を防ぎます。
- 制作費＝制作日×日当。工程ごとに円単位に四捨五入し、合算。予備日は請求対象外です。税の加算はしません。
- 1日は稼働日1日分。時間換算をせず、元ファイルの「1日の作業時間」は使いません。
- 休業日を避けて割り当てます。0.5日などの小数は、次の工程・予備日と同じ稼働日を共有できます。
- 全日数0の工程には日程を付けません。着手日が休業日なら次の稼働日から開始。
- 予定完了日は、その工程の最後の制作日または予備日です。
- 祝日の自動取得はありません。追加休業日へ手動入力してください。
- 元のExcelの完了日は固定値なので、設定する休業日や着手日の違いにより再計算結果は変わります。

## カレンダー連携

ICSは稼働日・工程・制作/予備ごとの終日予定です。Googleカレンダーなどへ手動インポートしてください。外部カレンダーへの自動同期はありません。同じ計画を何度も取り込む場合の重複処理はカレンダー側に依存します。

「書き出す → PDFを書き出す」で、A4横向き固定のPDFを直接ダウンロードします。日本語フォントを同梱し、文字を選択・検索・コピーできるテキストとして出力します。ブラウザーの印刷設定に依存せず、ネット接続も不要です。選択中のタブに関係なく、見積・工程一覧、着手月から完了月までの全カレンダー、計画全期間のガントチャートを出力し、各セクションの前で改ページします。ガントは28日単位で分割。長文は折り返し、1ページを超える表は次ページへ続きます。余白は約5mmです。

「印刷」も残しています。こちらはブラウザーの印刷機能で、セクションごとに改ページします。ブラウザーの印刷設定が優先される場合は用紙をA4横・倍率100%にし、ヘッダーとフッターをオフにしてください。

PDF用日本語フォントはGoogle FontsのNoto Sans JPを使用しています（SIL Open Font License 1.1、`src/assets/fonts/OFL.txt`）。元の可変フォントから400ウェイトを固定し、画面ヒント・合字の処理を除去したTTFを同梱しています。

## 開発

```powershell
npm install
npm run dev
```

Vite開発用ポートは `3007`（既存の3000〜3006を回避）。サーバーは利用者が起動します。

```powershell
npm test
npm run build
```

ビルド結果は単一HTMLの `dist/index.html`。React・Excelパーサーも同梱します。
